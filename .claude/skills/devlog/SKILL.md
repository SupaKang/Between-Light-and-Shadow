# Devlog — 개발 일지 작성

오늘 작업을 구조화된 마크다운으로 기록한다. git 커밋을 의미 단위로 묶어 `## ` 섹션으로 구성하고 `docs/devlog/`에 저장한다.

> 저장 경로: `docs/devlog/{YYYYMMDD}.md`
> 당일 파일 존재 시: 기존 내용 아래에 `---` 구분선 후 추가 (append)

---

## 감지 & 트리거

### 자동 감지
- 한국어: "devlog", "devlog 써줘", "개발 일지", "작업 기록", "오늘 작업 정리", "일지 써줘", "작업 일지", "개발 로그"
- 영어: "dev log", "write devlog", "log today's work"

### 수동 호출
| 커맨드 | 동작 |
|--------|------|
| `/devlog` | 현재 프로젝트 devlog 작성 |

---

## STEP 0: 컨텍스트 수집 (자동)

실행 즉시 아래를 **병렬로** 수집:

```bash
pwd
git branch --show-current 2>/dev/null || echo "(no git)"
git log --oneline --since="midnight" 2>/dev/null || echo "(no commits today)"
git log --oneline -15 2>/dev/null
git diff --stat HEAD~1 2>/dev/null || echo "(no diff)"
date +%Y%m%d
date +%Y-%m-%d
```

이후 `docs/devlog/{YYYYMMDD}.md` 존재 여부를 Read로 확인.
존재하면 기존 내용을 읽고 **append 모드**로 진행.

프로젝트 키는 `BLS` (Between Light and Shadow) 고정.

---

## STEP 1: 모드 선택

```
📝 Devlog — BLS / {YYYY-MM-DD}
   브랜치: {branch} | 오늘 커밋: {N}개{append_note}

모드를 선택하세요:
  ⚡ 빠른 기록 — git 커밋 자동 구성 (확인만)
  📋 상세 기록 — 의사결정·블로커·다음스텝 포함
```

`{append_note}`: 기존 파일 있으면 ` | ⚠️ 기존 내용 있음 → 아래에 추가`

- "빠르게", "간단히", "자동" → 빠른 기록 자동 선택
- "상세히", "자세히", "전체" → 상세 기록 자동 선택
- 오늘 커밋이 없으면 상세 기록으로 자동 전환

---

## STEP 2A: 빠른 기록

git 커밋을 의미 단위로 묶어 `## ` 섹션으로 자동 구성한다.

### 출력 템플릿

```markdown
# BLS Dev Log — {YYYY-MM-DD}

## {작업 그룹 제목}
{관련 커밋들의 핵심 내용을 2-4줄 서술식으로 기술}

### {세부 항목 (필요 시)}
- {내용}: {상세}
- {내용}: {상세}

## {다른 작업 그룹}
{내용}
```

**커밋 그룹화 규칙**:
- 같은 기능/모듈 관련 커밋은 하나의 `## ` 섹션으로 묶는다
- 커밋 해시/메시지를 그대로 나열하지 않고 "무엇을 왜" 서술식으로 작성
- 세부 내역은 `### ` 또는 불릿으로 처리
- 1개 커밋이라도 `## ` 섹션 1개로 작성

---

## STEP 2B: 상세 기록

자동 생성된 작업 섹션을 보여준 후 3가지를 순차 질문한다.

```
📝 자동 생성된 작업 내용:
{## 섹션들 미리보기}

추가 정보 (없으면 엔터로 건너뜀):
1️⃣ 의사결정 사항이 있었나요?
   예: "REST → GraphQL 전환 — 클라이언트 요구사항 변경"
```

사용자 입력 후:
```
2️⃣ 블로커나 미해결 이슈가 있나요?
   예: "인증 토큰 만료 처리 미완료"
```

사용자 입력 후:
```
3️⃣ 다음 스텝은 무엇인가요?
   예: "테스트 커버리지 80% 달성, 스테이징 배포"
```

### 상세 템플릿

```markdown
# BLS Dev Log — {YYYY-MM-DD}

## {작업 그룹 제목 1}
{상세 내용}

### {세부 항목}
- {내용}: {상세}

## {작업 그룹 제목 2}
{내용}

## 의사결정
- **{결정}**: {이유}

## 블로커 & 이슈
- [ ] {이슈}: {상태/다음 액션}

## 다음 스텝
- [ ] {할 일 1}
- [ ] {할 일 2}
```

입력이 없는 구조 섹션(`## 의사결정` 등)은 **통째로 생략**.  

---

## STEP 3: 저장

저장 전 미리보기를 제공하고 확인을 받는다.

```
📄 미리보기:
{생성된 내용}

저장 경로: docs/devlog/{YYYYMMDD}.md
{append: "기존 파일에 추가합니다." | new: "새 파일을 생성합니다."}

저장할까요?
```

확인 후:
1. `docs/devlog/` 디렉토리 생성 (없으면)
2. **신규**: `{YYYYMMDD}.md` 로 Write
3. **Append**: 기존 내용 읽기 → 아래에 `\n---\n` 추가 → 새 섹션 추가 → Write

저장 완료:
```
✅ Devlog 저장: docs/devlog/{YYYYMMDD}.md
```

---

## 파일 형식 규칙

| 항목 | 규칙 |
|------|------|
| 파일명 | `YYYYMMDD.md` (8자리 숫자, `docs/devlog/README.md` 규칙) |
| 헤더 | `# BLS Dev Log — {YYYY-MM-DD}` |
| 작업 섹션 | `## `  |
| 세부 내용 | `### ` 또는 불릿 |
| 구조 섹션 | `## 의사결정` / `## 블로커 & 이슈` / `## 다음 스텝` |
| Append 구분 | `---` (수평선) |

---

## 규칙

- `## ` 섹션 제목 = 실제 작업 항목
- 커밋 메시지 나열 금지 — 반드시 의미 단위로 묶어 서술
- 저장 전 반드시 미리보기 제공 (덮어쓰기 금지)
- 빈 섹션 헤더 금지 (입력 없으면 통째로 생략)
- git 없는 경로: git 섹션 건너뛰고 수동 입력 요청
- `docs/devlog/README.md` 규칙(한 일 / 변경 파일 / 남은 일) 준수: 변경 파일은 `### 변경 파일` 불릿으로 포함
