# ROM 분석 진행 기록

## 완료

- 원본 롬은 읽기 전용으로 처리했다.
- 2,097,152 bytes를 16KiB 단위 128개 뱅크로 분리해 지문·엔트로피·포인터 후보·명령어 후보·2bpp 반복률을 기록했다.
- 헤더와 SHA-1/SHA-256을 기록했다.
- LR35902/GBZ80 명령어 길이를 적용한 후보 디코더를 추가했다. 현재 결과는 코드 영역이 확정되지 않은 상태의 참고용 후보 목록이다.

## 현재 판단

- 정적 분석만으로는 코드·맵·문자열·그래픽 경계를 확정할 수 없다.
- 따라서 원본 에셋 추출이나 복제는 하지 않고, 분석 결과는 108의 입력·상태·화면 전환·데이터 스키마 설계에만 사용한다.
- 후보 디스어셈블리의 헤더 영역은 정상적인 실행 코드 영역으로 간주하지 않는다. 실제 코드 영역은 뱅크 전환과 진입점 추적을 추가 검증해야 한다.

## 다음 자동 작업

1. 점프·호출 대상의 뱅크/주소를 정규화한다.
2. 메모리 뱅크 경계를 고려한 제어흐름 후보를 만든다.
3. 그래픽 후보와 코드 후보를 분리하는 신뢰도 점수를 추가한다.
4. 결과를 `ROM_OBSERVATION_REPLACEMENT_SPEC.md`의 108 시스템 교체 항목과 연결한다.
