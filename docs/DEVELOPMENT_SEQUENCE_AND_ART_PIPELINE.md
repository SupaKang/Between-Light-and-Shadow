# 108: 음양견문록 — 순차 개발 계획 및 아트 파이프라인

문서 상태: 실행 계획 v0.1

## 1. 전체 진행 원칙

한 번에 전체 콘텐츠를 만들지 않고, 플레이 가능한 수직 슬라이스를 먼저 완성한다. 각 단계는 `기획 승인 → 구현 → 아트 통합 → 플레이 테스트 → 용량 측정 → 다음 단계 승인`의 게이트를 통과해야 한다.

확정 설정은 유지한다: 조선 민속 판타지, 음양당, 108종 요괴, 3마리 파티, 5종 상태이상, 유물의 양날 효과, 320×180, 16×16 타일, 1.44MB 제한.

## 2. 순차 개발 로드맵

### 0단계 — 기준선 고정

- `PROJECT_MASTER.md`를 SSOT로 지정
- 현재 코드·문서·실행 파일 크기 재측정
- ROM 참고 범위와 원본 복제 금지 기준 확정
- `TODO / VERIFY / TEST` 목록 작성

완료 기준: 빌드 명령, 산출물 경로, 용량 측정 방식이 문서화됨.

### 1단계 — 플레이 진입 흐름

- Boot → Title → New Game → Prologue → Character Setup
- 저장 슬롯 생성 및 기본 플래그
- 한글 텍스트 줄바꿈과 대화 입력

완료 기준: 새 게임을 시작해 주인공 집까지 도달 가능.

### 2단계 — 첫 탐험 루프

- 마을 허브 1개
- 16×16 타일 필드 1개
- 4방향 이동, 조사, NPC 대화, 출구 이벤트
- 회복 지점과 메뉴 오버레이

완료 기준: 집 ↔ 마을 ↔ 필드를 왕복 가능.

### 3단계 — 전투 및 계약

- 1v1 턴제 전투
- 기술 4슬롯 구조
- HP/Qi, 민첩 턴 순서, 승패
- 약화 상태와 계약 결과
- 5종 상태이상은 전투 엔진을 먼저 구현하고 UI를 뒤에 통합

완료 기준: 첫 야생 요괴를 약화시켜 계약하거나 패배할 수 있음.

### 4단계 — 수집 관리

- 최대 3마리 파티
- 요괴 도감 108 슬롯
- 레벨 및 등급 데이터 구조
- 유물 2종과 즉시 파괴

완료 기준: 계약한 요괴를 파티에 넣고 도감에서 확인 가능.

### 5단계 — 첫 Vertical Slice

- 마을, 필드, NPC, 야생 요괴, 전투, 계약, 유물, 서브퀘스트
- 음양당 사건과 연결되는 짧은 메인 목표
- 첫 보스와 다음 지역 잠금 해제

완료 기준: 처음부터 보스 승리까지 20~40분 플레이 가능.

### 6단계 — 확장

- 지역을 하나씩 추가
- 지역별 신규 요괴·민담 퀘스트·유물 추가
- 마지막에 108종 전체 콘텐츠를 채움

## 3. 새 아트 제작 파이프라인

기존의 “AI 이미지 생성 → 픽셀화” 중심 방식은 일관성·저작권 추적·애니메이션 품질 문제가 있으므로, AI는 레퍼런스 탐색과 아이디어 보조로 제한하고 최종 원본은 자체 도트 제작물로 관리한다.

### A. 아트 바이블 작성

먼저 다음을 고정한다.

- 해상도: 필드 16×16~16×24, 전투 32×32~48×48
- 팔레트: 기본 16색, 특수 연출 최대 32색
- 선 처리: 순수 픽셀 계단, 안티앨리어싱 금지
- 명암 방향, 외곽선 색, 눈·손·무기 표현 규칙
- 조선시대 복식·건축·문양의 조사 출처와 사용 범위

산출물: `palette.gpl`, 타일 규격표, 스프라이트 템플릿, 금지 사례 시트.

### B. 실루엣 우선 설계

요괴마다 먼저 흑백 16×16 또는 48×48 실루엣을 제작한다. 이름과 특징만으로 식별 가능한지 확인한 뒤 색을 입힌다.

- 1차: 3개 실루엣 후보
- 2차: 기획자·아트 디렉터 선택
- 3차: 전승 출처 또는 창작 표기와 핵심 특징 검수

산출물: `concept/`, 요괴 ID, 출처, 특징 태그.

### C. 제한 팔레트 도트화

선정된 실루엣을 공통 팔레트로 수작업 도트화한다. 자동 양자화는 보조 단계로만 사용하고, 눈·문양·손·무기·외곽선은 수동 수정한다.

- 필드 버전: 16×16 또는 16×24
- 전투 버전: 32×32 기본, 중요 요괴 48×48
- 방향: 필드 4방향, 전투 정면/후면 필요 여부를 데이터로 관리
- 색상: 투명색 포함 4bpp 우선

산출물: PNG 원본, indexed PNG, 미리보기 시트.

### D. 애니메이션 제작

처음부터 모든 프레임을 만들지 않는다.

- 필드: 대기 2프레임, 걷기 방향별 2프레임
- 전투: 대기 1~2프레임, 공격 2~4프레임, 피격 2프레임
- 보스 연출: 재사용 가능한 이펙트 프레임을 조합

프레임 수가 늘어날수록 용량을 측정하고, 차이가 작은 프레임은 공통 프레임 또는 좌우 반전으로 대체한다.

### E. 타일·맵 제작

타일을 개별 그림이 아니라 조합 가능한 세트로 만든다.

1. 바닥 4종
2. 경계·절벽 4종
3. 길·물·문·나무·바위
4. 건물 외벽과 실내 세트
5. 조사물·표지판·출구 표시

타일은 16×16 논리 타일 안에서 반복되도록 설계하고, 맵 JSON에는 타일 ID와 이벤트 ID만 저장한다.

### F. UI 및 폰트 제작

- 9-slice 창 1종을 기본으로 하고 색상 테마만 교체
- 메뉴 아이콘은 8×8 또는 12×12 단색 실루엣
- 한글 폰트는 실제 사용 글리프만 추출
- 대화창, 전투 HUD, 도감 카드가 동일한 프레임 규칙을 공유

### G. 기술 변환 및 용량 검증

아트 원본과 게임 삽입 파일을 분리한다.

```text
art_src/          편집 가능한 원본과 메타데이터
art_review/       승인된 미리보기
art_build/        indexed PNG / raw binary
src/generated/    C++ constexpr 또는 압축 배열
```

변환 도구는 다음을 자동 검사한다.

- 허용 해상도
- 팔레트 외 색상 사용 여부
- 투명색 규칙
- 중복 프레임 해시
- RLE 적용 전후 크기
- 요괴 ID와 파일명 일치

최종 빌드에서는 PNG를 직접 읽지 않고 4bpp raw 또는 RLE 데이터만 포함한다.

## 4. 아트 승인 게이트

각 에셋은 다음 순서를 통과해야 한다.

1. 기획: 요괴의 역할·등급·전승/창작 출처 확인
2. 아트: 실루엣 식별성·팔레트·시대감 확인
3. 개발: 실제 화면 크기·애니메이션·충돌 영역 확인
4. QA: 배경에서 식별 가능한지, 다른 에셋과 겹치지 않는지 확인
5. 빌드: 용량과 ID 무결성 확인

반려 사유도 메타데이터에 기록해 같은 문제를 반복하지 않는다.

## 5. 첫 제작 목표

첫 아트 스프린트는 전체 108종이 아니라 다음만 만든다.

- 주인공 필드 스프라이트 1종
- 마을 NPC 2종
- 기본 바닥·길·나무·집 타일 세트
- 첫 야생 요괴 1종의 필드/전투 버전
- 전투 HUD와 대화창
- 회복처와 출구 아이콘

이 세트로 Stage 1~3을 실제 플레이 테스트한 뒤 스타일을 고정한다. 스타일이 고정되기 전에는 108종 대량 제작을 시작하지 않는다.
