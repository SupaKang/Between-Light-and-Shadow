# 108: 음양견문록 — 롬 분석 기반 독립 플레이 구조

## 원칙

분석 결과는 화면 전환, 입력 응답, 상태 관리, 데이터 분리의 참고 자료로만 사용한다. 원본 코드·그래픽·문자열·음악·맵은 사용하지 않는다.

## 플레이 흐름

`부트 → 타이틀 → 저장 슬롯 → 음양당 붕괴 프롤로그 → 마을 필드 → NPC/오브젝트 상호작용 → 야생 조우 → 턴제 전투 → 약화/계약 → 결과 → 필드 복귀`

## 화면 상태 명세

| 상태 | 입력 | 필수 데이터 | 108 독립 구현 |
|---|---|---|---|
| 부트/타이틀 | 확인, 취소 | 설정, 저장 목록 | 1920x1080 출력, 960x540 논리 캔버스 |
| 필드 | 4방향, 확인, 메뉴 | 맵, 충돌, 플레이어, NPC | 32x32 타일, 카메라 추적 |
| 대화 | 확인, 취소 | 화자, 문장, 선택지 | 초상화·로그·분기 |
| 전투 | 방향, 확인, 취소 | 파티, 적, 기술, 상태 | 3인 파티, 민첩 순서 |
| 계약 | 확인, 취소 | 약화 수치, 계약 확률 | 계약 성공/실패·도감 등록 |
| 메뉴 | 방향, 확인, 취소 | 파티·유물·도감·설정 | 즉시 복귀 가능한 계층 메뉴 |
| 저장 | 확인, 취소 | 월드·파티·퀘스트 | 슬롯 3개, 무결성 검사 |

## 시스템 모듈

- `GameState`: 현재 화면과 전환 요청을 단일 상태 머신으로 관리
- `InputRouter`: 장치 입력을 게임 액션으로 변환
- `WorldRuntime`: 맵·충돌·NPC·상호작용·인카운터 처리
- `BattleRuntime`: 턴 순서·기술·피해·5종 상태이상 처리
- `CollectionRuntime`: 약화·계약·파티·도감·성장 처리
- `DataRegistry`: 요괴 108종·기술·아이템·유물·대사 참조
- `SaveRuntime`: 버전·체크섬·슬롯·로드 실패 복구

## 우선 구현 순서

1. 화면 상태 머신과 입력 라우터
2. 필드 이동·충돌·상호작용
3. 1대1 전투 및 결과 복귀
4. 약화·계약·도감 등록
5. 3마리 파티·메뉴
6. 저장/로드
7. 수직 슬라이스 콘텐츠

## 검증 기준

- 모든 화면은 확인/취소 입력으로 막히지 않고 이전 상태로 복귀한다.
- 전투 종료 후 필드 위치와 파티 상태가 보존된다.
- 계약 성공 시 도감과 파티 데이터가 동시에 일관되게 갱신된다.
- 저장 후 재실행해 필드·파티·퀘스트 상태가 동일하게 복원된다.
- 원본 롬의 파일·바이트·에셋을 런타임에 요구하지 않는다.
