# 다음 실제 작업 실행 계획 — ROM 관찰 및 재구축 착수

## 1. 목표

다음 작업의 목표는 ROM을 분해해 원본 게임을 복제하는 것이 아니다. `108: 음양견문록`의 독자 엔진이 참고할 수 있도록 다음 네 가지를 측정하는 것이다.

1. 입력이 화면과 상태를 어떻게 바꾸는가
2. 플레이어·카메라·충돌·상호작용이 어떤 규칙으로 동작하는가
3. 대화·메뉴·전투 UI가 어떤 순서와 위치를 사용하는가
4. 저장·로드 후 어떤 상태가 보존되는가

## 3. 1차 작업 — VBA에서 플레이 관찰

### 3.1 실행 준비

1. `VBA.exe` 실행
2. ROM 열기
3. 에뮬레이터 배율을 고정하고 필터를 끔
4. 정상 속도와 기본 키 설정 확인
5. 새 게임용 세이브 상태로 시작
6. 관찰 화면마다 파일명에 시나리오·순번·프레임 또는 시각을 기록

VBA가 화면 캡처·입력 기록·프레임 진행을 지원하지 않으면 화면 녹화와 수동 입력 로그를 사용한다. 관찰 도구 자체의 보정 기능이 게임 동작을 바꾸지 않는지 확인한다.

### 3.2 첫 관찰 시나리오

#### RUN-01 부팅

- 전원/리셋부터 타이틀 완성까지
- 로고와 타이틀 애니메이션
- 첫 입력 허용 시점
- 메뉴 항목과 초기 커서

#### RUN-02 새 게임

- 새 게임 선택 입력
- 이름 입력 최대 길이
- 초기 방 진입
- 첫 NPC 대화 페이지 수
- 이동 허용 시점

#### RUN-03 초기 방

- 상하좌우 각 1회 이동
- 벽·가구·출구 충돌
- 조사 가능 오브젝트
- 계단·문·층 이동

#### RUN-04 첫 마을

- NPC 접근 거리
- NPC를 바라보는 방향과 확인 입력
- 대화 중 방향키 처리
- 마을 서비스 위치
- 건물 출입과 맵 전환

#### RUN-05 첫 필드

- 카메라 추적
- 지형별 이동 가능 여부
- 야생 조우 발생 위치
- 조우 전환 효과

#### RUN-06 첫 전투

- 전투 진입 화면
- 아군·적 스프라이트 위치
- 명령 메뉴 커서 초기 위치
- 기술 선택·취소
- 턴 처리·로그·승리·패배

#### RUN-07 저장

- 저장 메뉴 진입
- 저장 가능 위치
- 저장 전후 화면
- 재실행 후 위치·파티·아이템·플래그

## 4. 기록 양식

각 행동은 다음 표에 기록한다.

| 항목 | 기록 내용 |
|---|---|
| Run ID | RUN-01 등 |
| Step | 순번 |
| Input | 키, 방향, 누름 시간 |
| Before | 화면·위치·커서·활성 상태 |
| After | 화면·위치·커서·플래그 변화 |
| Timing | 프레임 또는 초 |
| Screenshot | 캡처 파일명 |
| Decision | `108` 적용 / 변형 / 제외 |
| Confidence | 확정 / 추정 / 재검증 |

## 5. 2차 작업 — 관찰 결과를 명세로 변환

RUN-01~RUN-03이 끝나면 다음 명세를 먼저 작성한다.

### `INPUT_BEHAVIOR_SPEC.md`

- 방향 입력 우선순위
- 키 반복 지연
- 확인·취소 소비 규칙
- 대화·메뉴·전투 중 입력 잠금

### `SCREEN_LAYOUT_SPEC.md`

- 160×144 원본 관찰 좌표
- 960×540 논리 좌표 변환 규칙
- Full HD 2배 출력 규칙
- 대화창·메뉴·전투 HUD 앵커

### `WORLD_INTERACTION_SPEC.md`

- 이동 단위
- 충돌 박스
- NPC 상호작용 범위
- 문·계단·워프
- 카메라 추적과 맵 경계

## 7. 4차 작업 — 회귀 테스트

관찰한 입력을 골든 트레이스로 만든다.

```json
{
  "id": "RUN-03-room-exit",
  "inputs": [
    {"command":"move_down","frames":12},
    {"command":"move_right","frames":24},
    {"command":"confirm","frames":1}
  ],
  "checkpoints": [
    {"screen":"home","player_tile":[6,8]},
    {"screen":"village","player_tile":[3,10]}
  ],
  "status":"VERIFY"
}
```

실행 결과는 플레이어 위치, 화면 ID, 커서, 대화 페이지, 플래그만 우선 비교한다. 픽셀 전체 비교는 아트가 고정된 뒤 추가한다.

## 8. VBA의 한계와 보조 도구 조건

VBA에서 다음이 가능하면 1차 관찰을 계속한다.

- ROM 실행
- 화면 확대/필터 고정
- 스크린샷 또는 녹화
- 세이브/로드
- 입력 재현

다음 기능이 필요할 때는 BGB 같은 디버거를 보조 도구로 추가한다.

- CPU 현재 주소와 명령어 추적
- 실행·접근 브레이크포인트
- VRAM viewer
- 메모리 쓰기 감시
- joypad 입력 처리 루틴 추적

BGB는 이런 디버거 기능을 제공하지만, 도구별 에뮬레이션 차이를 줄이기 위해 최종 플레이 관찰은 VBA와 실제 화면 결과를 기준으로 교차 확인한다. [BGB 매뉴얼](https://bgb.bircd.org/manual.html)

## 10. 금지 사항

- ROM을 저장소에 복사하지 않음
- 원본 그래픽·문자·음악을 게임 에셋으로 등록하지 않음
- 관찰하지 않은 좌표·프레임·확률을 추정해 확정값으로 기록하지 않음
- 아트 제작을 회색 박스 상호작용 검증보다 먼저 시작하지 않음
- 원본의 명칭·캐릭터·스토리·수치 테이블을 `108` 데이터에 사용하지 않음
