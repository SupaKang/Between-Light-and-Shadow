# ROM 플레이 관찰 로그

대상: 제공된 `포켓몬스터 골드 (한).gbc`
목적: 원본 콘텐츠 복제가 아닌, 90년대 휴대용 RPG의 입력·화면·상호작용·상태 전이를 관찰해 `108: 음양견문록`의 독자 런타임을 설계하기 위함

## 1. 관찰 대상 식별

- 파일 크기: 2,097,152 bytes
- ROM bank 추정: 64 × 32KiB
- SHA-256: `9C273E86E6120C6A038160CCB0153B8B20425B84FC08A496281C1D1BCAC492F6`
- 헤더 타이틀 관찰값: `POKEMON_GLDAAUK?`
- CGB 플래그: `C0`
- 카트리지 타입: `10`
- ROM 크기 코드: `06`
- RAM 크기 코드: `03`
- 관찰 일시: 2026-09-06
- 관찰자: Codex 자동 기록 초안

`Gen2Recomped` README가 명시한 캐논 US Gold SHA-1과 이 파일의 해시는 다르므로, 이 ROM이 해당 프로젝트의 지원 대상인지 먼저 확인해야 한다. 실행 또는 임포트 실패 여부를 게임 설계 사실로 해석하지 않는다.

## 2. 기록 규칙

각 관찰은 다음 형식으로 남긴다.

```text
[OBS-ID]
입력: 어떤 키/버튼을 몇 프레임 또는 몇 초 눌렀는가
이전 상태: 화면, 플레이어 위치, 커서, 활성 이벤트
관찰 결과: 화면 변화, 사운드, 이동, 플래그 변화
기대 규칙: 108에 적용할지 여부
증거: 스크린샷/영상/입력 로그 파일명
상태: OBSERVED | VERIFY | REJECTED
```

관찰 결과를 설계에 사용할 때는 화면 모양보다 다음 우선순위를 둔다.

1. 입력에 대한 결과의 일관성
2. 상태 전이의 예측 가능성
3. 충돌·상호작용 판정
4. UI 위치와 커서 동작
5. 연출·색상·사운드

## 3. 관찰 장비 및 실행 조건

- 에뮬레이터: `TODO` — 사용 에뮬레이터와 버전 기록 필요
- 입력 기록: `TODO` — 프레임 단위 입력 캡처 필요
- 화면 캡처: 원본 화면 비율을 유지한 PNG
- 속도: 정상 1배속
- 저장: 새 세이브로 시작
- 치트·터보·상태 저장: 사용하지 않음
- ROM 원본: 프로젝트에 복사하거나 커밋하지 않음

## 4. 필수 관찰 시나리오

### OBS-BOOT — 부팅과 타이틀

- 시작 상태에서 타이틀 표시까지 걸리는 시간
- 타이틀 애니메이션의 루프와 입력 가능 시점
- 새 게임·이어하기·옵션의 메뉴 항목
- 저장 파일이 없을 때의 이어하기 처리
- 확인·취소·방향 입력의 동작

상태: `VERIFY`

### OBS-NEWGAME — 새 게임 시작

- 새 게임 선택 후 첫 화면
- 이름 입력의 최대 글자 수와 커서 이동
- 초기 위치·방향·소지품·플래그
- 첫 NPC 대화의 페이지 수
- 첫 이동이 가능해지는 정확한 시점

상태: `VERIFY`

### OBS-MOVEMENT — 필드 이동

기록할 값:

- 논리 이동 단위
- 한 번 누름과 길게 누름의 차이
- 키 반복 시작 지연과 반복 간격
- 방향 전환만 가능한지, 이동과 동시에 가능한지
- 벽·NPC·오브젝트·맵 경계 충돌
- 플레이어 발 기준점
- 카메라 추적 시작/정지 조건

상태: `VERIFY`

### OBS-INTERACTION — NPC와 조사

- NPC를 바라보고 확인해야 하는가
- 인접 칸, 접촉, 시야 중 판정 방식
- 조사물별 상호작용 우선순위
- 이벤트 후 플레이어 위치와 방향
- 같은 NPC를 다시 조사했을 때의 결과

상태: `VERIFY`

### OBS-DIALOGUE — 대화창

- 창의 화면 좌표와 크기
- 한 줄 문자 수와 최대 줄 수
- 자동 진행 여부
- 확인 버튼을 눌렀을 때 페이지 넘김/종료 우선순위
- 대화 중 방향키 입력 처리
- 선택지의 커서 시작 위치와 취소 방법

상태: `VERIFY`

### OBS-MENU — 필드 메뉴

- 메뉴 호출 버튼
- 메뉴 창의 위치·크기
- 항목 순서와 커서 초기 위치
- 하위 메뉴 진입·취소 스택
- 메뉴 중 월드 애니메이션 정지 여부
- 메뉴에서 필드로 복귀했을 때 위치와 방향

상태: `VERIFY`

### OBS-MAP — 맵 전환

- 문·계단·출구·워프의 판정 방식
- 화면 전환 효과와 입력 잠금
- 도착 위치·방향
- 맵별 음악 변경 시점
- 이벤트 진행 중 맵 전환 제한

상태: `VERIFY`

### OBS-ENCOUNTER — 야생 조우

- 조우 가능 지형
- 안전 구역
- 걸음 수와 조우 확률의 관계
- 조우 직전 효과
- 전투 종료 후 필드 복귀 위치
- 연속 조우 방지 여부

상태: `VERIFY`

### OBS-BATTLE — 전투 진입과 명령

- 전투 진입 화면 구성
- 아군·적 위치와 HUD 좌표
- 명령 메뉴의 항목 순서
- 커서 이동과 취소
- 턴 시작·기술 선택·연출·로그·턴 종료 순서
- 아이템·교체·도주 처리

상태: `VERIFY`

### OBS-RESULT — 전투 결과

- 승리·패배·도주 후 화면
- 경험치·레벨업·아이템·플래그 처리 순서
- 패배 후 복귀 위치
- 계약/포획 실패와 성공의 입력 흐름

상태: `VERIFY`

### OBS-SAVE — 저장과 재개

- 저장 가능한 위치
- 저장 메뉴 진입·확인·취소
- 저장 중 입력 잠금
- 재실행 후 위치·방향·파티·아이템·스토리 플래그 보존
- 손상 또는 빈 저장 데이터 처리

상태: `VERIFY`

## 7. 현재 판정

- ROM 식별: `OBSERVED`
- ROM 내부 코드·에셋의 게임 재사용: `REJECTED`
- 실제 프레임 단위 플레이 관찰: `VERIFY`
- 관찰 기반 C++/Win32 또는 대체 런타임 재구축: `PLANNED`
- 첫 구현 착수 조건: 이동·대화·메뉴·맵 전환 관찰 로그 최소 1세트 완료
