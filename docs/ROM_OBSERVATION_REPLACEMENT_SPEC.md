# ROM 관찰 후 `108: 음양견문록` 교체 요소 보고서

문서 상태: v1.0 / 관찰 사실과 설계 제안 분리

## 1. 관찰 범위

### 확인된 사실

- 대상 ROM은 2,097,152 bytes의 GBC 이미지다.
- 32KiB 기준 64개 ROM bank로 구성된다.
- GBC 대응 플래그와 배터리 RAM 카트리지 정보가 헤더에 존재한다.
- GBC 계열 플레이 구조는 타일·메타타일·맵 이벤트·스크립트·전투·저장 데이터가 결합된 상태 머신으로 이해할 수 있다.
- `Gen2Recomped`는 ROM을 실행하는 에뮬레이터가 아니라, 합법적으로 보유한 캐논 ROM을 임포트해 Lua 런타임에서 데이터와 동작을 재현하는 프로젝트다. [프로젝트 README](https://github.com/UNDERdecoded/Gen2Recomped)

### 아직 직접 검증하지 않은 사실

다음은 실제 에뮬레이터에서 프레임·입력·화면을 기록해야 한다.

- 제공된 한국어 ROM의 정확한 게임 버전과 지역별 차이
- 실제 타이틀·초기 방·첫 마을의 픽셀 좌표
- NPC 상호작용 범위와 이벤트 우선순위
- 메뉴 커서 이동·취소·대화 페이지 규칙
- 전투 명령 선택·턴 연출·상태이상 표시 타이밍
- 저장 데이터의 실제 필드와 체크섬 방식

위 항목은 모두 `VERIFY`로 관리한다. ROM에서 추출한 원본 코드·그래픽·문자·음악·맵은 `108`에 사용하지 않는다.

## 2. 교체 전략

기준은 “동작의 골격은 검증하고, 의미와 콘텐츠는 교체”다.

```text
관찰 대상                 108 교체 결과
────────────────────────────────────────────
플레이어 이동             음양 조사자 이동
NPC/이벤트 스크립트       민담·야사·음양당 사건
몬스터 조우               야생 요괴 조우
포획                      약화 후 계약
파티                      최대 3마리 요괴
도감                      108 요괴 견문록
아이템                    유물·부적·약초·계약 도구
전투 기술                 음양술·민속 의식·요괴 특성
지역/체육관 구조          마을·산길·하천·폐사찰·음양당 거점
라이벌/악의 조직          음양당 잔당과 지역 인물
```

## 3. 상세 교체 요소

### 3.1 부팅·타이틀·새 게임

**관찰할 요소**

- 입력을 받기 시작하는 프레임
- 타이틀 메뉴의 커서 초기 위치
- 새 게임과 이어하기의 분기
- 저장 파일이 없을 때의 처리

**108 교체**

- 제목: `108: 음양견문록`
- 메뉴: `새 기록 / 이어하기 / 설정 / 종료`
- 새 기록 시작 시 음양당 붕괴의 잔상과 주인공 목적을 3~5개 대화 상자로 표현
- 저장 파일이 없으면 `이어하기`는 선택 불가

### 3.2 주인공과 초기 설정

**관찰할 요소**

- 이름 입력 길이와 커서 규칙
- 초기 위치·방향·소지품
- 첫 대화 후 이동 가능 시점

**108 교체**

- 주인공: 음양당 사건을 조사하는 견습 기록자
- 이름은 6~8자 범위 `VERIFY`
- 초기 소지품: 기록첩, 약초 1개, 빈 계약 부적 3개 `TODO`
- 초기 목표: 마을 기록관에게 붉은 안개 사건을 묻기

### 3.3 필드 이동

**관찰할 요소**

- 이동 단위
- 키를 누르고 있을 때 반복 속도
- 방향 전환과 이동의 우선순위
- 벽·NPC·문·계단 충돌
- 카메라가 플레이어를 따라가는 방식

**108 교체**

- 논리 해상도 960×540, 출력 1920×1080
- 32×32 논리 타일
- 필드 캐릭터 32×48
- 이동은 4방향만 우선 구현
- 대각선 입력은 두 방향을 합성하지 않고 무시
- 캐릭터 기준점은 발 중앙으로 고정

### 3.4 NPC·조사·대화

**관찰할 요소**

- NPC를 바라보고 확인할 때만 대화하는지
- 인접 칸·접촉·시야 중 어떤 조건인지
- 대화창의 위치·줄 수·페이지 넘김
- 이벤트 종료 후 플레이어 위치와 방향

**108 교체**

- 기록관: 메인 목표와 도감 시스템 설명
- 약초상: 회복 아이템과 상태이상 설명
- 장터 상인: 유물·계약 도구 판매
- 조사물: 우물, 장독, 당산나무, 낡은 부적
- 대화 종료 후 마지막 입력을 이동으로 재사용하지 않음

### 3.5 맵과 워프

**관찰할 요소**

- 맵 경계와 워프 타일
- 문·계단·동굴의 전환 효과
- 맵 진입 시 플레이어 위치와 방향
- 건물 내부/외부 로딩 방식

**108 교체**

- 각 맵은 `tiles`, `collision`, `warps`, `actors`, `events`를 분리한 데이터로 저장

### 3.6 야생 조우

**관찰할 요소**

**108 교체**

## 4. 개발 순서

### 1차: ROM 관찰 오라클

입력 로그와 스크린샷 체크포인트를 만든다. 코드 없이도 `Title → Home → Village → Field`를 관찰할 수 있어야 한다.

### 2차: 회색 박스 재현

아트 없이 플레이어, 벽, NPC, 대화창, 전투 메뉴만 구현한다. 이 단계에서 조작감과 UI 비율을 고정한다.

### 3차: 108 데이터 교체

기존 게임의 몬스터·아이템·지역 개념을 그대로 복사하지 않고, 108의 요괴·계약·유물·민담 데이터로 교체한다.

### 4차: 고품질 아트 통합

Full HD 기준의 32×48 필드 캐릭터, 128×128 전투 요괴, 256×256 대화 초상, 32×32 타일을 순서대로 통합한다.

### 5차: 회귀 검증

동일한 입력 로그를 반복 실행해 플레이어 위치, 화면 전환, 커서, 대화 상태, 전투 결과, 저장 결과가 매번 동일한지 확인한다.

## 5. 보고 판단

`Gen2Recomped`의 핵심 장점은 실행 가능한 콘텐츠를 만들기 전에 데이터·스크립트·맵·렌더링을 분리한 점이다. 그러나 이 프로젝트는 ROM 기반 Pokémon 재현기이고, Generation II 구성요소는 저장소의 라이선스 설명상 재배포·포크가 제한되어 있다. 따라서 `108`에는 다음만 적용한다.

- 구조적 아이디어: 적용
- 코드 직접 복사: 적용하지 않음
- ROM 원본 데이터 사용: 적용하지 않음
- ROM 관찰 기반 입력·UI·상호작용 테스트: 적용
- 108 전용 데이터·아트·스토리: 새로 제작
