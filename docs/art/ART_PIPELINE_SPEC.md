# ART PIPELINE & TECH FEASIBILITY SPEC
## (일러스트 기반 픽셀화/코드화 파이프라인 및 1.44MB 용량/개발시간 절감 분석)

---

## 1. 듀얼 비율 비주얼 컨셉 체계

- **필드 탐험**: `2등신 SD 치비 도트` (16x24 픽셀)
  - 작은 화면에서 맵의 시야 확보 및 아기자기한 레트로 RPG 탐험 감성 극대화.
- **전투 / 컷신 / 도감**: `6등신 웹툰/만화풍 일러스트 도트` (48x48 ~ 64x64 픽셀)
  - 진지한 퇴마 서사와 개성 있는 요괴의 비주얼 임팩트 전달.

---

## 2. 파이프라인: 원화 -> 픽셀화 -> 코드화 4단계

```text
[Step 1. 원화 컨셉 생성] -> [Step 2. 팔레트 양자화] -> [Step 3. 다운스케일 픽셀화] -> [Step 4. 바이너리 코드화]
(6등신 만화 캐릭터 디자인)   (전통 16/32색 매핑)      (전투 64x64 / 필드 16x24)   (RLE/4bpp 배열화)
```

1. **원화 컨셉 생성 (Image Generation)**: 
   - 의상(갓, 도포, 쾌자, 부적), 헤어, 무기, 요괴의 시그니처 특징을 통일하여 6등신 캐릭터를 1회 디자인.
2. **팔레트 양자화 (Color Quantization)**: 
   - 생성된 일러스트를 프로젝트 공통 32색 팔레트(오방색 기반)로 강제 매핑하여 일관된 톤 앤 매너 유지.
3. **해상도 다운스케일 & 픽셀 보정 (Pixelation)**:
   - **전투/컷신용**: 64x64(또는 48x48) 크기로 다운스케일 후 외곽선/음영 디더링 정돈.
   - **필드용**: 원화의 시그니처 파츠(갓 색상, 도포 무늬, 헤어스타일)만 추출해 16x24 2등신 치비 도트로 파생 생성.
4. **바이너리 압축 및 C++ 코드화 (Code Conversion)**:
   - 4-bit Indexed Color (픽셀당 0.5바이트) + Run-Length Encoding(RLE) 압축을 통해 C++ `constexpr uint8_t[]` 바이트 배열로 직렬화.

## 3. 용량 (1.44MB 제한) 검증 계산

| 에셋 유형 | 해상도 / 포맷 | 원시 크기 | 4bpp + RLE 압축 크기 | 108종 총 용량 |
| :--- | :--- | :--- | :--- | :--- |
| **필드 SD 스프라이트** | 16x24 (4프레임) | 1,536 B | **약 380 B** | **~40 KB** |
| **전투 요괴/캐릭터** | 48x48 (단일) | 2,304 B | **약 650 B** | **~70 KB** |
| **보스/컷신 포트레이트** | 64x64 (20종 한정) | 4,096 B | **약 1,100 B** | **~22 KB** |
| **총 그래픽 에셋 용량** | - | - | - | **약 132 KB** |

> **용량 결론**: 그래픽 에셋 목표 할당량(600 KB) 대비 **약 132 KB로 22% 수준만 사용**하므로 1.44MB 플로피 디스크 용량 한계를 **100% 여유롭게 만족**합니다.

## 4. 개발 시간 절감 효과

1. **디자인 일관성 확보**: 원화 1장으로 필드 2등신 도트와 전투 6등신 도트의 색상/복식/아이템이 자동 일치.
2. **도트 수작업 시간 80% 단축**: AI 시안 생성 -> 자동 양자화/픽셀화 스크립트 -> 아티스트 최소 수정.
3. **단일 C++ 빌드 파이프라인**: 이미지 파싱 툴이 이미지를 바로 `const uint8_t g_Sprite_Gumiho[]` 헤더로 자동 추출하여 엔진에 즉시 바인딩.
