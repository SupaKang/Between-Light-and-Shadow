# 108: 음양견문록 — Full HD 전환 제안 스펙

상태: 신규 기준안 / 기존 `PROJECT_MASTER.md` 대체 전 승인 필요

## 1. 기존 문서 확인 결과

기존 아트·기술 문서는 다음 기준을 사용한다.

- 320×180 내부 해상도
- 16×16 타일
- 필드 16×16~16×24 스프라이트
- 전투 32×32~48×48 스프라이트
- 16~32색 제한 팔레트
- 1.44MB 독립 실행 파일
- `gen1` 및 포켓몬 비교 자료를 제작 기준으로 사용

이 기준은 작은 화면과 플로피 용량에는 적합하지만, 제공된 샘플의 고밀도 환경 표현·큰 전투 일러스트·세밀한 캐릭터 포즈를 재현하기에는 부족하다. 따라서 아래 제안은 화면·아트·용량 기준을 새로 정의한다.

## 2. 유지·변경·폐기

### 유지

- 조선시대 민속 판타지 세계관
- 음양당 궤멸 메인 스토리
- 요괴 108종, 한국 전승 70% / 해외 전승 및 창작 30%
- 3마리 파티
- 레벨 1~50, 등급 I~V, 기술 최대 4개
- 화상·빙결·봉인·마비·공포
- 유물의 버프+디버프 양날 구조
- Windows 독립 실행, 오프라인, 서버·브라우저 의존성 없음

### 변경

- 출력: 1920×1080 Full HD, 16:9
- 내부 논리 캔버스: 960×540, 최종 2배 nearest-neighbor 확대
- 필드 논리 타일: 32×32
- 필드 캐릭터: 32×48 또는 32×64
- 전투 일반 요괴: 96×96~128×128
- 전투 보스: 160×160~256×256
- 대화 초상: 192×192~256×256
- UI 본문: 24~32px 픽셀 폰트, 중요 제목 40~64px
- 에셋 포맷: 원본 PNG/레이어 파일과 런타임 압축 데이터 분리

### 폐기 또는 유보

- 1.44MB 실행 파일 강제 제한: `VERIFY` 후 신규 용량 예산으로 대체
- 4색 또는 저밀도 16색 화면을 전체 게임에 강제하는 규칙
- `gen1`, `Pokemon` 명칭을 제품 코드·에셋 경로에 사용하는 관행
- 참고작과의 수치·맵 면적 비교를 품질 기준으로 삼는 방식

## 3. 새 시각 목표

스타일 이름은 `Joseon Folklore Cinematic Pixel`로 한다.

제공 샘플의 공통 특징인 고밀도 픽셀 묘사, 제한된 녹색 계열 톤, 재질 중심 타일, 강한 외곽선, 큰 전투 요괴, 캐릭터 초상을 기준으로 삼는다. 단, 샘플의 특정 캐릭터·문양·구도는 복제하지 않는다.

### 화면별 방향

- 필드: 탑다운 3/4 시점, 32×32 타일, 건물과 당산나무를 큰 랜드마크로 구성
- 대화: 필드 화면 위에 반투명 창을 두고 192×192 이상 초상과 3~4줄 대화 표시
- 전투: 요괴를 화면의 25~40% 높이로 배치하고, 대기·공격·피격 실루엣을 명확히 구분
- 메뉴: 고정 창보다 배경과 연결된 두 패널 구조를 사용하되 선택 정보는 항상 우선 노출
- 지역 전환: 짧은 전경·배경 패럴랙스 또는 색조 전환으로 지역 정체성 부여

## 4. Full HD 화면 구성

### 필드

- 게임 뷰포트: 960×432
- 하단 대화/상태 영역: 960×108
- 한 화면 표시: 가로 30타일 × 세로 13.5타일에 해당하는 카메라 영역
- 실제 구현에서는 타일 경계가 화면 중앙에 걸려도 카메라 픽셀 정렬 유지

### 전투

- 상단 적 HUD: 320×96
- 적 전투 스프라이트 영역: x=560~900, y=48~300
- 아군 전투 스프라이트 영역: x=80~430, y=160~410
- 하단 명령·로그 영역: y=432~540
- 원본 논리 좌표는 960×540으로 저장하고 1920×1080에서 2배 출력

### 메뉴

- 좌측 탐색 패널: 280×540
- 중앙 콘텐츠 패널: 440×540
- 우측 상세 패널: 240×540
- 도감·파티·유물은 동일한 카드 프레임을 공유

## 5. 새 아트 스펙

| 자산 | 제작 캔버스 | 런타임 권장 | 기준 |
|---|---:|---:|---|
| 필드 주인공 | 32×48 | 4방향×4프레임 | 얼굴, 복식, 무기, 발 위치 판독 |
| 필드 NPC | 32×48 | 2~4프레임 | 직업별 실루엣과 복식 차이 |
| 필드 요괴 | 32×32~48×48 | 2~4프레임 | 종족 특징과 이동 중심축 |
| 전투 요괴 | 96×96~128×128 | 대기/공격/피격 | 얼굴, 사지, 장식, 그림자 |
| 보스 요괴 | 160×160~256×256 | 4~8프레임 | 화면 지배력, 비대칭 특징, 연출 |
| 대화 초상 | 192×192~256×256 | 표정 2~4종 | 인물 정체성과 표정 |
| 기본 타일 | 32×32 | 1~4층 조합 | 재질 명암 4~6단, 가장자리 연결 |
| 랜드마크 | 64×64~256×256 | 조립 오브젝트 | 건물·나무·우물·제단 식별 |

팔레트는 더 이상 전체 16색으로 제한하지 않는다. 기본 팔레트는 지역별 24~32색, 전투 요괴별 추가 강조색 4~8색, 화면 전체 최대 64색을 권장한다. 내부 팔레트는 색상 수보다 명도 단계와 재질 대비를 우선한다.

## 6. 게임 전체 구조

### Act 0 — 진입

부팅 → 타이틀 → 새 기록/이어하기 → 설정 → 프롤로그 → 주인공 설정

### Act 1 — 첫 계약

집 → 마을 허브 → 기록관 대화 → 첫 필드 → 야생 요괴 조우 → 1v1 전투 → 계약

### Act 2 — 기록과 파티

회복처 → 파티 3칸 → 도감 → 첫 유물 → 필드 조사 → 단발 민담 퀘스트

### Act 3 — 지역 확장

마을 주변 → 산길/하천/폐사찰 등 지역별 허브 → 지역 요괴군 → 보스 → 음양당 단서

### Act 4 — 본편

5개 핵심 지역, 지역 보스, 메인 스토리, 사이드 퀘스트, 유물 조합, 등급 성장

### Act 5 — 종결

음양당 본거지 → 최종 전투 → 108 도감 후속 목표 → 엔딩 분기

## 7. 기술 스펙 변경

- C++17과 Win32/소프트웨어 프레임버퍼는 유지
- 렌더 버퍼를 960×540로 확장하고 Full HD 출력 시 정수 배율 2배 사용
- 창 크기가 1920×1080보다 작을 경우 960×540 또는 1280×720 정수 배율을 우선
- 32비트 ARGB는 유지하되 런타임 에셋은 indexed/RLE/공통 팔레트 압축 사용
- 저장·데이터 포맷은 기존 ID 기반 구조를 유지
- 사운드는 압축 파일 또는 절차 합성으로 관리

## 8. 신규 용량 예산

플로피 제한을 폐기하더라도 독립 실행성과 빠른 배포를 위해 첫 목표를 64MB 이하로 둔다.

| 영역 | 목표 |
|---|---:|
| 실행 파일·코드 | 5MB 이하 |
| 요괴·캐릭터 원본/런타임 에셋 | 24MB 이하 |
| 타일·랜드마크·UI | 12MB 이하 |
| 사운드·음악 | 18MB 이하 |
| 데이터·저장·여유분 | 5MB 이하 |
| 합계 | 64MB 이하 |

이는 최종 확정치가 아니라 `TEST`용 목표치다. 첫 Vertical Slice 후 실제 수치를 갱신한다.

## 9. 즉시 실행 순서

1. 기존 320×180 렌더 좌표와 Full HD 논리 좌표를 분리
2. 960×540 카메라·UI 레이아웃 구현
3. 32×32 타일 1세트와 32×48 캐릭터 3종 제작
4. 128×128 전투 요괴 1종과 192×192 초상 1종 제작
5. 마을 화면과 전투 화면을 Full HD로 통합
6. 기존 테스트를 화면 해상도·스케일링 테스트로 확장
7. Vertical Slice 플레이 후 새 용량 예산 재측정
