# 108: 음양견문록 — GBC 구조 분석 기반 플레이 흐름 기획안

문서 상태: 제안안 v0.1 / `TODO`, `VERIFY`, `TEST`는 미확정 항목

## 1. 분석 범위와 저작권 경계

분석 대상은 사용자가 제공한 다음 로컬 파일이다.

- 파일: `C:\Users\seank\Downloads\포켓몬스터 골드 (한).gbc`
- 크기: 2,097,152 bytes / 2 MiB / 64 x 32 KiB banks
- SHA-256: `9C273E86E6120C6A038160CCB0153B8B20425B84FC08A496281C1D1BCAC492F6`
- 헤더 관찰값: CGB flag `C0`, cartridge type `10`, ROM size `06`, RAM size `03`
- 화면 기준: 160 x 144, 8 x 8 tile 기반

이 문서는 원본 게임의 에셋·문자·음악·맵·코드를 추출하거나 재사용하지 않는다. 관찰 가능한 기술적 패턴과 플레이 단계만 참고하여 108의 독자적인 규칙·명칭·그래픽으로 재설계한다. 원본 ROM의 정확한 bank별 데이터 위치와 디스어셈블 결과는 전용 도구와 에뮬레이터 검증 전까지 `VERIFY`다.

## 2. 관찰된 구조와 우리 프로젝트에 적용할 원칙

### 2.1 데이터/렌더링 구조

GBC 계열 게임은 작은 8 x 8 그래픽 타일을 조합해 배경·건물·지형을 만들고, 더 큰 논리 단위인 메타타일과 맵 블록을 통해 반복되는 공간을 저장하는 방식이 적합하다. 캐릭터는 필드용 소형 스프라이트와 전투용 대형 스프라이트를 분리하고, 대화·메뉴는 고정된 창 영역으로 처리한다.

108에 적용한다.

- 필드: 16 x 16 논리 타일, 반복 가능한 메타타일, 맵 이벤트 테이블
- 캐릭터: 16 x 16~16 x 24 필드 스프라이트 / 32 x 32~48 x 48 전투 스프라이트
- UI: 320 x 180 내부 해상도, 9-slice 창, 고정 앵커와 2줄 한글 텍스트
- 데이터: 코드에 산재시키지 않고 압축 가능한 ID 기반 테이블로 관리
- 에셋: 원본과 무관한 오방색 제한 팔레트, 자체 도트 실루엣과 타일 세트

### 2.2 플레이 구조에서 참고할 패턴

1. 부팅 → 타이틀 → 저장 슬롯 → 짧은 프롤로그 → 플레이어 이름/출발점
2. 안전한 허브 공간 → 첫 튜토리얼 상호작용 → 인접 필드 진입
3. 이동/조사 → 야생 조우 → 전투 명령 → 결과 및 회복
4. 약화 → 계약 → 파티 편성 → 도감 기록
5. 마을 서비스와 메뉴를 통해 반복 루프를 짧게 회귀
6. 새 지역 진입 때 새 규칙 하나만 추가하고, 메인 목표를 갱신

## 3. 세 역할의 합의

### 시니어 게임 기획자

핵심은 “요괴를 발견하고 약화시켜 계약한 뒤, 다음 지역의 단서를 여는 반복”이다. 초반부터 108종을 노출하지 않고 첫 20분에 이동·조사·1v1 전투·계약·회복·파티 교체를 순서대로 가르친다. 포켓몬의 이름·지역·캐릭터·UI를 복제하지 않고, 음양·계약·민담 기록이라는 고유 동기를 전면에 둔다.

### 시니어 게임 개발자

모든 화면은 `Scene`으로 분리하고 상태 전이는 명시적으로 만든다. 필드 이벤트와 전투를 동일한 입력 추상화 위에 두며, 저장 데이터는 현재 장면·플래그·파티·도감·유물만 기록한다. Phase 1의 320 x 180과 1.44MB 제약을 유지하고, 기능 추가마다 Release 파일 크기를 측정한다.

### 아트 디렉터

원본의 시각 언어가 아니라 “조선 민속 판타지 기록물”을 기준으로 한다. 필드는 탁한 청록·먹색·황토, 선택 강조는 주홍·금색으로 제한한다. 필드와 전투의 스프라이트 비율은 분리하되 동일한 실루엣 규칙과 4~8색 팔레트를 공유한다. 한글 가독성을 위해 장식보다 창 구조와 여백을 우선한다.

## 4. 실제 플레이 단계와 화면 설계

### Stage 0 — 부팅과 타이틀

`SCR-00 Boot`: 검은 화면, 짧은 로고, 입력 대기. 저장 파일을 읽기 전에 오류를 표시한다.

`SCR-01 Title`: 로고, `새 기록 / 이어하기 / 설정 / 종료`. 이어하기는 저장 슬롯이 없으면 비활성화한다.

### Stage 1 — 프롤로그와 출발

`SCR-02 Prologue`: 음양당 사건의 잔상과 주인공의 목적을 3~5개의 대화 상자로 전달한다.

`SCR-03 Character Setup`: 이름 입력과 기록 방식 선택. 성별·직업 등 미확정 요소는 추가하지 않는다.

`SCR-04 Home Interior`: 조사 가능한 책상·문·보관함을 배치한다. 조사 2회 후 첫 목표를 활성화한다.

### Stage 2 — 첫 튜토리얼 루프

`SCR-05 Village Hub`: 회복처, 기록관, 장터, 출구를 제공한다. NPC 한 명이 요괴 조우와 계약을 설명한다.

`SCR-06 Route Field`: 16 x 16 타일, 1개 출구, 1개 조사물, 1종 야생 요괴. 첫 조우는 강제 1회, 이후 확률 조우다.

`SCR-07 First Battle`: 명령은 `기술 / 계약 / 교체 / 도주` 2 x 2. 첫 전투에서는 기술과 계약만 유효하게 한다.

`SCR-08 Contract Result`: 성공·실패·기록 갱신을 보여주고, 성공 시 파티 또는 보관 공간으로 보낸다.

### Stage 3 — 수집과 관리

`SCR-09 Party`: 최대 3마리, 선두 변경, 상태·HP·Qi 확인.

`SCR-10 Codex`: 108 슬롯, 미발견/조우/계약 상태를 구분. 실제 전승 출처와 창작 여부는 데이터 필드로 명시한다.

`SCR-11 Artifact`: 유물의 동시 버프/디버프, 즉시 파괴 확인. 초기에는 2종만 제공한다.

### Stage 4 — 첫 지역 목표

`SCR-12 Shrine/Investigation`: 필드 조사와 민담형 단발 퀘스트를 연결한다. 보상은 경험치·유물·계약 기회 중 하나다.

`SCR-13 Boss Battle`: 1v1을 유지하되 상태이상과 교체를 해금한다. 승리 후 다음 지역의 이동 조건을 연다.

### Stage 5 — 반복 가능한 본편 루프

`SCR-14 Region Gate`: 지역명, 권장 레벨, 발견 가능한 요괴 범주, 해금 조건을 표시한다.

`SCR-15 Save/Exit`: 마을 또는 안전 지점에서 저장한다. 전투 중 저장은 불가하다.

## 5. 권장 상태 전이

```text
Boot -> Title
Title -> NewGame -> Prologue -> Setup -> Home
Home <-> Village <-> Field
Field -> Encounter -> Battle
Battle -> ContractResult -> Field
Battle -> Defeat -> Village
Village -> Party/Codex/Artifact/Quest
Village -> RegionGate -> Field(next region)
AnySafeScene -> Save -> PreviousScene
```
